# RP9 / RP11 统一生成架构

状态：基础离线实现；原生验收未完成。不得将结构检查通过解释为宿主兼容性证明。

## 分层与开发规则

RP/1 → Python 语义检查与布局 → 版本化编译计划/场景 IR → Node.js 后端 → 共享 Axure 容器。

- 业务与布局在共享层实现一次。`scripts/backends/` 注册 RP9、RP11 编码策略，负责元件字段、富文本版本、输入类型及默认库页名。
- 交互写入使用文件实际版本；动作对象在构造时选择目标字段，保留最终版本适配检查。后续新增动作应将版本编码集中到后端，不能在工作流里增加版本判断。
- 容器层共享 manifest、压缩、记录及引用重排。编辑现有工程不应通过反编译后全量重建来替代局部编辑。
- 能力注册表为 `scripts/capabilities.mjs`。实现、支持方式与原生验证证据独立；历史 `core` 标签仅引用历史文档，不自动升级原生证据。
- 文件生成与剪贴板入口分离。文件生成失败不自动调用 GUI；遗留 GUI 装配器仍仅支持 RP9。

## 接口规范

生成、截图重建、同步和改稿使用 `targetVersion: 9 | 11`；CLI 编译/生成/装配使用 `--axure-version 9|11`。

新建优先级：调用参数 → RP/1 `target` → RP9。已有工程和改稿以文件/基线版本为约束，不支持已有工程跨版本转换。环境变量 `AXURE_TARGET_VERSION` 不参与高层文件生成目标解析。

模板可显式传 `template`，否则通过 `AXURE_BLANK_TEMPLATE_RP9` / `AXURE_BLANK_TEMPLATE_RP11` 配置。模板与工程版本必须相同。异步任务入队固定目标和模板，并记录输入指纹。

编译计划与基线增加 `formatVersion: 2`、`targetVersion`、`delivery: "file"`。旧计划需重新编译，旧基线需重新生成工程建立；不自动猜测迁移。

截图接口移除 `version` 和 `guiPaste` 参数；使用 `targetVersion` 直接生成文件。剪贴板放置继续使用独立 Axvg 工具。

## 支持边界

共同实现：多页、矩形/统一圆角、文字、分组、嵌入 PNG/JPEG、普通/密码输入类型、变量、点击跳转、改字、显隐、启用/禁用与变量赋值。编译器为绑定生成的加载和输入事件也可装配。

RP11 在装配前拒绝面板、母版、中继器、自适应视图和未开放动作；保留源码指针诊断。RP9 继续使用原有高级能力实现。密码类型已编码，但密码遮蔽显示仍需原生验收。

不对外承诺任意 Axure 工程均能无损反编译/三方合并；同步仅支持现有可识别属性，未知变更应报告。

## 验证与交付要求

export AXURE_BLANK_TEMPLATE_RP9=/absolute/native-rp9-blank.rp

原生验收必须分别使用对应 Axure：打开 → 检查独立可编辑元件与密码遮蔽 → 点击测试各交互 → 修改文本/位置 → 保存 → 关闭 → 重开 → 再预览。记录应用构建号、系统版本、文件 SHA-256、截图和逐项结果。缺模板、权限或菜单访问时记录未完成，不计为成功。
